## Current Findings

### High: node acceptance can still become a hashless Stack failure

CCC 1.17.0 receives the node's transaction hash before awaiting cache marking and returning it (`packages/core/src/client/client.ts:936-939` at the release source). Stack adopts the hash only after that complete promise resolves in `packages/bot/src/bot/loop.ts:239-259`, `apps/interface/src/action/actionTransaction.ts:90-113`, and `packages/validation/src/tester/runtime/testerAttempt.ts:145-157`. If cache marking fails after node acceptance, the bot emits a terminal hashless send failure, the interface treats the attempt as pre-broadcast and releases it, and validation records no accepted hash. This does not normally cause an automatic bot retry, but it loses reconciliation identity and permits an operator or UI resubmission while the first transaction may already be accepted.

Derive and retain the deterministic raw transaction hash before broadcast. Every failure after the broadcast boundary must carry that hash and enter pending reconciliation rather than pre-broadcast handling.

### High: L1 scans still have no total-work or stuck-cursor boundary

`packages/utils/src/utils.ts:25-39` drains every item from a supplied scan into memory. Bare `collect` calls also materialize L1 generators, including the pool/order paths in `packages/sdk/src/client/sdk_l1_class.ts:133-143`. `pageSize` bounds only each indexer request. It neither bounds total pages/items nor exposes cursor advancement, so Stack cannot stop CCC's repeated-full-page-cursor failure. The audit dependency gate reproduced more than 10,000 collected items before its controlled timeout.

Give cell and transaction pagination one owner that advances and checks the cursor and enforces an explicit total-work budget. Delete or restrict unbounded L1 materializers rather than adding independent caller caps.

### High: production update stops the sole bot before validating its replacement

`scripts/ickb-bot-systemd-update.sh:291-303` stops the service, mutates the in-place checkout, installs, checks, and only then restarts. Any failure leaves the sole service down; after a successful pull, an install or check failure also leaves the deployment mutated. There is no automatic rollback or readiness gate.

Prepare and validate a sibling release while the current service runs, switch atomically, require readiness, and roll back the service target on failure. Do this before further investment in the custom unit parser.

### Medium: browser reload discards pending transaction ownership

`apps/interface/src/query/pendingTransactionQuery.ts:35-55` stores pending identity only in the in-memory React Query client. Infinite garbage-collection time preserves same-session remounts but does not survive a reload. Reloading during confirmation therefore removes the local guard against a second submission before the existing hash is reconciled. This compounds the hash-loss boundary above: both paths can leave the UI with no pending owner while L1 may already have accepted a transaction.

Persist the account-, chain-, and transaction-bound pending identity before presenting the attempt as sent, hydrate it before enabling submission, and clear it only after terminal reconciliation. Keep private signing state out of persistence.

### Medium: bounded public preflight races CCC's shared fallback index

`packages/node-utils/src/chain.ts:180-192` configures two public HTTP endpoints and concurrently requests genesis and tip through one client. CCC 1.17.0's fallback transport mutates one shared endpoint index, so one request can redirect another request's retry to an already failed endpoint. This affects omitted-URL finite actors using Stack's HTTP pool; exclusive `rpcUrl` configurations use `fallbacks: []` and do not hit this path.

Upgrade or patch the fallback owner, or avoid shared automatic fallback state for concurrent calls. Do not reproduce CCC's endpoint scheduler in Stack.

### Medium: active launcher output is outside the storage quota

`scripts/bot/launcher/storage/prepare.ts:35-48` applies quota only before launch, and `scripts/bot/launcher/storage/retention.ts:16-18` excludes the active slot from deletion. `scripts/bot/launcher/logs.ts:43-52` then appends without a runtime bound. A healthy long-running bot can exceed the configured quota. It can also make live-stimulus validation fail once an unread event delta exceeds `MAX_EVENT_READ_BYTES` in `packages/validation/src/supervisor/stimulus/runtime/liveBotStimulusWait.ts:154-159`.

Give the active writer one runtime quota/rotation owner that includes events, stderr, launch history, and artifacts. Preserve complete terminal evidence or stop explicitly when the bound cannot be maintained.

### Low: Stack can construct an iCKB output rejected by deployed Logic

`packages/core/src/udt.ts:362-372` encodes one iCKB change output as `Uint128`, while deployed Logic commit `454cfa966052a621c4e8b67001718c29ee8191a2` rejects each co-executed iCKB output above `u64::MAX` at `scripts/contracts/ickb_logic/src/entry.rs:121-126`. Generic order data also correctly permits `Uint128` values, so a global order-codec clamp would be the wrong owner. Normal deposit batching is far below this limit, and this review found no current live trigger; retain it as a low-reachability future boundary rather than an observed production failure.

At the iCKB-specific transaction boundary, reject or split each output above the deployed per-cell limit. Preserve generic xUDT/order `Uint128` compatibility.

## Simplification Order

1. Replace unbounded L1 collection variants with one pagination owner that owns cursor progress and total work.
2. Compute transaction identity once before broadcast and route every post-broadcast outcome through one hash-bearing reconciliation path.
3. Give the interface one persisted pending lifecycle. Treat confirmation depth and aggregate timeout as explicit policy inputs, not nested retry behavior.
4. Give launcher storage one runtime quota owner; delete the prelaunch-only approximation once active rotation or bounded stopping owns the contract.
5. Fix fallback concurrency and HTTP timer cleanup in CCC through upgrade or patch rather than adding Stack transport wrappers.
6. Replace in-place production mutation with validated sibling releases, readiness, atomic switching, and rollback before simplifying systemd inspection.

Do not clamp generic xUDT/order values to `u64`; the narrower deployed iCKB output contract owns that restriction. Do not merge actor subprocesses or remove process-group cleanup to reduce code size.
