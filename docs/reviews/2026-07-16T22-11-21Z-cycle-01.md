## Findings

### High: matching search can miss an executable profitable match

`packages/order/src/matching/order_match_search.ts:196` retains only the locally highest-gain next state. A temporarily non-positive or allowance-constrained state can be necessary to reach a profitable cross-direction combination, but that state is discarded without an upper-bound proof.

A differential reproduction used five valid dual-ratio groups `(free CKB, UDT, ratio)` of `(119,210,2/13)`, `(13,2,6/1)`, `(147,152,10/5)`, `(123,130,14/9)`, and `(217,116,2/13)`, allowance `(181,0)`, exchange weights `(16,3)`, step `61`, fee `0`, and cap `5`. The current search returned no match after five candidates. Exhaustive traversal found a unique four-partial match with deltas `(CKB +297, UDT +25)` and gain `4,827`; `OrderManager.addMatch` accepted and constructed it.

Impact: the bot and fresh-order guard can skip actionable liquidity. The search needs exhaustive traversal or a branch-and-bound/Pareto pruning proof. This property is not suitable for static lint; retain a differential oracle test.

### High: supervisor classification consumes obsolete bot outcome names

`packages/validation/src/supervisor/classification/supervisorBotFailureClassification.ts:21` recognizes `timeout_after_broadcast`, `post_broadcast_unresolved`, and `terminal_rejection`. The current producer at `packages/bot/src/bot/loop.ts:306` emits `timeout` or `confirmation_failed`.

An actual-format `timeout` was classified as `bot_retryable_error`; `confirmation_failed` became `bot_terminal_error`; both lost `txHashes`. Existing tests pass because fixtures use the retired vocabulary.

Impact: coverage, incident classification, and post-broadcast handling become incorrect. Align the consumer with the producer-owned event contract and test producer-format records through `classifyActorResult`. Static lint cannot prove semantic string contracts across independently constructed records.

### High: launcher liveness proof can expire before tester funds are spent

`packages/validation/src/supervisor/stimulus/preflight/liveBotStimulusPrepare.ts:23` proves launcher liveness before two potentially long preflights. `packages/validation/src/supervisor/stimulus/runtime/liveBotStimulusSession.ts:52` then creates the on-chain tester stimulus without revalidating that proof.

The proof in `packages/validation/src/supervisor/stimulus/preflight/liveBotStimulusPreflight.ts:114` establishes only that recorded PID numbers currently exist; a stale record can accept reused PIDs after a crash or reboot. If the bot exits during preflight, the tester can still commit an order and then wait on stale logs.

Impact: the live validation flow can spend tester funds without the bot process it intended to exercise. Bind proof to boot/process-start identity and revalidate the same launcher immediately before the on-chain side effect. This is a freshness-boundary test, not a lint rule.

### High: signing UI omits whether conversion creates a standing order

`apps/interface/src/action/transaction.ts:60` retains the transaction, maturity, fee, and optional notice but discards the SDK conversion kind. The SDK returns `collect-only`, `direct`, `order`, or `direct-plus-order`, and `packages/sdk/src/client/sdk_conversion_class.ts:130` can mint the standing order.

Impact: users cannot distinguish transaction paths with materially different lifecycle and liquidity consequences before signing, contrary to the product requirement that transaction intent be clear. Preserve the discriminated conversion kind in `TxInfo`, render the exact path before confirmation, and test every conversion variant. Static lint cannot establish informed transaction intent.

### Medium: DAO output-limit check accepts unresolved DAO inputs

`packages/dao/src/dao_output_limit.ts:27` checks only `input.cellOutput?.type`. Normal decoded transaction inputs may contain only `previousOutput`, leaving `cellOutput` unresolved. A reproduced 65-output transaction with DAO activity only in an unresolved input passed `assertDaoOutputLimit` and would later fail immutable DAO validation.

SDK-created paths currently resolve these inputs, but the exported helper accepts `TransactionLike`. For transactions above 64 outputs, resolve missing input metadata or reject an indeterminate input set. This requires a regression test with an unresolved input.

### Medium: order fee model undercounts each partial by 76 bytes

`packages/order/src/matching/order_match_context.ts:43` models a partial as `36 + occupiedSize`. CCC serialization showed `275` marginal bytes for a standard order whose `occupiedSize` is `163`, while the model charges `199`.

With allowance `340`, 1:1 valuation, fee rate `1000`, and step `340`, a reproduced match had gross gain `211`, modeled fee `199`, and reported net `+12`; the serialized marginal fee was `275`, making net value `-64`.

Impact: thin-spread matches can be classified as profitable when they are loss-making. Derive and test the exact marginal serialized size for first and subsequent partials. ESLint cannot prove serialization economics.

### Medium: constructed order groups can self-certify origin provenance

`packages/order/src/model/cells.ts:512` rebuilds and validates an exported `OrderGroup` entirely from caller-supplied cells. It verifies internal relationships but does not prove that the supplied origin contents are the chain output committed by the claimed outpoint.

A genuine origin rejected a descendant with changed `Info`; replacing the origin with fabricated contents at the same claimed outpoint made `validatedOrderGroup` and `addMatch` accept it. Current in-repository callers are protected because they obtain groups through `findOrders`, but exported consumers are not.

Make resolved groups opaque/attested by the chain resolver or re-resolve at the transaction boundary. Static lint cannot establish chain provenance.

### Medium: negative fee rates turn losses into positive match candidates

`packages/order/src/matching/order_match_context.ts:44` accepts a negative `feeRate`. A reproduction with `-1000` made the mining fee negative and reported gain `593` for a trade whose gross value was `-1`. The direct SDK fee-rate read at `packages/sdk/src/client/sdk_l1_class.ts:342` also does not validate the returned value.

Reject negative fee rates at the public matching boundary and cover malformed custom clients. This is runtime input validation, not static lint.

### Medium: DAO-limit failure bypasses the existing fee-change fallback

`packages/sdk/src/client/sdk_base.ts:50` retries fee placement only for `ErrorTransactionInsufficientCapacity.isForChange`. If ordinary fee completion appends change to a 64-output DAO transaction, the assertion at line 73 sees 65 outputs and throws even when routing change into an existing eligible output would remain valid.

Preserve the pristine transaction and invoke the existing output-target retry when fee completion crosses the DAO limit. Add a 64-to-65 output regression case. This lifecycle interaction is not lintable.

### Medium: post-broadcast interface failures lose recoverable state

`apps/interface/src/action/actionTransaction.ts:52` obtains a hash before waiting, but a raw polling RPC rejection is rendered through the generic catch without that known hash. The `finally` block clears the frozen preview. The same function passes `Infinity` as the wait timeout at line 54, so permanently pending or dropped transactions can instead freeze the interface forever.

Impact: one failure mode tells the user the operation failed after a successful broadcast and loses the identifier; another never returns control. Model all post-broadcast failures as unresolved outcomes carrying the hash, use a finite timeout, and support confirmation retry without rebroadcasting. ESLint now catches the literal infinite timeout; the hash/state contract still needs tests.

### Medium: invalid amount text is changed into another financial intent

`apps/interface/src/shared/utils.ts:82` deletes unsupported characters. Pasting `-1` becomes `1`, `1e2` becomes `12`, and `1..2` becomes `1.2`; `apps/interface/src/view/Form.tsx:55` makes the transformed amount actionable.

Preserve invalid text, validate one fixed-point grammar, and disable transaction preview/signing with an explicit error. This needs parser and mounted-form tests rather than lint.

### Medium: wallet and transaction errors remain stale across recovery paths

`apps/interface/src/wallet/WalletConfigGate.tsx:38` discards the query `refetch` operation, while the error view offers only the wallet connector. A transient failure under the same signer key can remain cached. Separately, `apps/interface/src/action/Action.tsx:51` stores a send failure independently of amount, direction, and state identity, so a previous failure remains visible on a later signable preview.

Expose exact-query retry and scope attempt state to the preview identity. Add mounted tests for reject-then-retry with the same signer and reject-edit-refresh transaction flow.

### Medium: interface deployment workflow is undiscoverable

`apps/interface/.github/workflows/deploy.yml:1` is nested below the app. GitHub discovers workflows only under repository-root `.github/workflows`, so pushes to `master` never run this deployment. Its commands and artifact paths also assume the app is the repository root.

Move and adapt the workflow at the repository root or delete it if deployment is intentionally external. Structure lint now reports nested workflow files.

### Medium: frontend loading and motion violate stated product constraints

`apps/interface/src/main.tsx:3` eagerly imports the wallet/SDK stack before mounting static UI. The production build emitted one `1,066.88 kB` minified (`338.64 kB` gzip) entry chunk and a Vite warning. Combined with fixed reserved rows in `apps/interface/index.css:112`, constrained clients can see a mostly blank first viewport.

`apps/interface/src/action/ActionLayout.tsx:72` and `apps/interface/src/view/Form.tsx:165` also run repeating nonessential pulse animations without a reduced-motion policy, conflicting with the repository's WCAG AA target.

Mount a lightweight static shell before loading wallet interactivity, establish a measured entry budget, and stop or suppress nonessential repeating motion. Browser slow-load and `prefers-reduced-motion` checks are better owners than syntax lint.

### Medium: public API validation gives incomplete and unsupported assurance

`api-extractor.base.json:3` disables committed API reports, while package scripts such as `packages/core/package.json:42` use `--local`; no compatibility baseline is enforced. At the start of this cycle, dirty uncommitted Core, Order, and SDK package configs also downgraded `ae-forgotten-export`, allowing seven hidden public symbols to pass. Those dirty-checkout downgrades were removed, so API lint now fails on `OwnerEntityBase`, `ReceiptEntityBase`, `InfoBase`, `OrderBase`, `RatioBase`, `RelativeBase`, and `IckbSdkL1`.

Additionally, `pnpm-workspace.yaml:25` forces API Extractor 7.58.9 from its pinned TypeScript 5.9.3 implementation onto TypeScript 6.0.3. The tool confirmed it loaded 6.0.3 even though it relies on compiler internals.

Design the exported hierarchy, enable committed API reports in non-local CI mode, and use the API tool's supported compiler implementation. API Extractor owns forgotten exports and compatibility; dependency policy owns its compiler.

### Medium: toolchain and dead-code checks contain blind spots

- `pnpm-workspace.yaml:32` typechecks the Node 22.19 runtime floor against `@types/node` 25, permitting Node 25-only APIs to compile.
- `knip.jsonc:5` treats every `scripts/**/*.ts` file as an entrypoint. Standard Knip passed, while `--include-entry-exports` exposed 47 unused exports and 34 unused exported types.
- The cycle-start `vitest.config.mts` excluded runtime-bearing files solely because their names ended in `Types`, `_types`, or `types`. Those exclusions were removed; the expanded suite still reports 100% coverage.

Align Node types with the supported runtime, enumerate real script entrypoints, and keep runtime coverage independent of filenames.

### Medium: process environment safety defaults unsafe and lint is bypassable

`packages/validation/src/supervisor/runtime/command/supervisorCommandRun.ts:30` inherits all of `process.env` unless `inheritEnv === false`, while `packages/validation/src/supervisor/runtime/shared/supervisorTypes.ts:312` makes the opt-out optional. The source-structure rule recognizes only a literal call named `runCommand`; aliasing the function bypasses it.

Make an explicit minimal environment the API default or a required type-level choice. Runtime boundary tests should own the guarantee; syntax lint can remain defense in depth but is not proof.

### Medium: CI leaves checkout credentials available to dependency tooling

`.github/workflows/check.yaml:16` uses checkout's persisted credential, and the workflow has no explicit token permissions before executing the installed dependency graph through `pnpm check`.

Declare top-level `contents: read` and set checkout `persist-credentials: false`. Structure lint now reports both omissions.

### Low: node-utils documentation names a removed SDK export

`packages/node-utils/README.md:7` says `sendAndWaitForCommit(...)` remains in `@ickb/sdk`, while the current SDK barrel tests assert that it is absent and the replacement `waitTransaction` does not send. Update the example to show signer submission followed by waiting. An import-checked documentation example could own this contract.

### Low: ESLint duplicates invariant ownership

`eslint.config.mts:237` bans most type assertions through a generic syntax selector while line 407 also enables `@typescript-eslint/no-unsafe-type-assertion`. Core complexity and Sonar complexity use different thresholds, and unfinished-work comments have overlapping owners. This creates duplicate diagnostics and dual-disable pressure without stronger proof.

Retain one owner and one threshold per invariant. This is lint simplification, not a product behavior change.
