## Current Findings

### High: configured endpoints still have no runtime identity

`apps/bot/src/index.ts:118-131` still reduces the configured endpoint to `rpcConfigured: boolean`. Two same-chain/account/bounds configs using different exclusive endpoints therefore compare equal in live-stimulus identity validation. Bind a non-secret endpoint identity or perform a local non-logging equality proof. Never emit or hash credential-bearing URL text.

### Medium: concurrent preflight requests break the HTTP fallback pool

`packages/node-utils/src/chain.ts:140-152` supplies two HTTP transports to CCC, then concurrently requests genesis and tip. Installed CCC 1.17.0 `TransportFallback` mutates one shared transport index; when the primary fails, concurrent requests race that index. A focused counterexample with an unavailable primary and healthy secondary let one request fall back while the other rejected. Upgrade/patch the fallback owner or avoid shared mutable fallback state, and add a concurrent two-request regression.

### Medium: API approval reports are dirty-worktree prerequisites

`api-extractor.base.json:3-7` enables API reports, but all five `packages/*/etc/*.api.md` baselines are untracked. The current API gate passes only in this dirty checkout; a clean checkout cannot reproduce the approval state. Because packages are unpublished, disable `apiReport` and delete the 1,051 generated report lines while retaining declaration analysis, forgotten-export/release-tag diagnostics, builds, and Publint. Commit reports only when compatibility approval becomes a real release contract.

### Low: failed HTTP attempts can delay process exit after successful fallback

Installed CCC 1.17.0 `TransportHttp` clears its 30-second abort timer only after successful `fetch(...).json()`. A failed primary followed by successful fallback can print completion but keep the finite process alive until the failed attempt's timer fires. Patch/upgrade the HTTP transport to clear timers in `finally`; extend `packages/node-utils/test/fixtures/httpPublicClientProcess.ts` with failed-primary/successful-secondary behavior.

### Low: bounded endpoint behavior is not documented for operators

`packages/validation/src/supervisor/README.md:13` says omitted RPC configuration lets CCC choose defaults, but bounded bot/tester actors now request Stack's HTTP-only pool while the unbounded bot retains CCC's full default pool. Document that distinction after the fallback/lifetime contract is final.
