## Current Findings

### Medium: the hash-preserving sender bypasses CCC's maximum-fee guard

`packages/sdk/src/send/sign_and_send_transaction.ts:41-50` signs and calls `signer.client.sendTransactionNoCache` directly. CCC 1.17.0's ordinary `Client.sendTransaction` first computes the transaction fee rate and rejects values above its default maximum of 10,000,000, then calls the no-cache transport and marks the cache (`packages/core/src/client/client.ts:923-939` at CCC release commit `a74017fc99e00c0e3cbd2a45afe150908b8ab734`). The new helper no longer executes that final pre-broadcast financial safety check.

A focused mock transaction whose `getFeeRate` would return 10,000,001 was broadcast successfully: fee checks were zero and send calls were one. Every current Stack product sender uses this helper through `apps/bot/src/index.ts:145-146`, `apps/interface/src/action/actionTransaction.ts:130-139`, or `packages/validation/src/tester/runtime/testerAttempt.ts:146-153`. Normal product transactions are completed with a capped sampled fee rate, which limits practical reachability, but it does not replace the send-time ceiling and the helper is exported publicly.

Restore an explicit maximum-fee decision after signing and before recording pending identity or starting RPC. Preserve the hash-before-RPC contract only after pre-broadcast validation succeeds, and add an over-limit regression that proves the transport is not called.

### Medium: the hook fixture no longer models pending-query initialization

Production `Action` passes a hydrated pending-state value as React Query `initialData` at `apps/interface/src/action/Action.tsx:101-108`. The hook fixture at `apps/interface/test/hook/fixtures/environment.ts:157-183` recognizes the pending query only when `initialData` is a function, so it returns unrelated generic query data. The interface package therefore fails two ownership tests: waiting renders `request conversion` instead of `stop waiting`, and restored ownership renders `request conversion` instead of `retry confirmation`.

The real React remount test passes with a fresh `QueryClient`, so this is a test-model and coverage-gate regression rather than evidence that production reload persistence failed. Update the mock to model both supported `initialData` forms or otherwise align it with the actual query contract. Do not weaken the ownership assertions or change production behavior solely to satisfy the stale mock.

### Low: an inconsistent node hash mutates cache before it is rejected

After a no-cache send succeeds, `packages/sdk/src/send/sign_and_send_transaction.ts:52-60` marks the signed transaction in CCC's cache before comparing the returned node hash with the local transaction hash. On mismatch, the helper throws only after `markTransactions` has recorded status `sent`, marked inputs unusable, and marked outputs usable. The SDK test at `packages/sdk/test/send/sign_and_send_transaction.ts:58-72` currently requires this ordering. Bot handling further classifies every `TransactionBroadcastError`, including a known hash mismatch, as `broadcast_ambiguous` and continues confirmation with the local hash at `packages/bot/src/bot/loop.ts:257-267`.

Compare hashes before cache mutation. Distinguish an inconsistent response from unresolved transport failure so callers do not present a response already proven inconsistent as ordinary broadcast ambiguity.

### Low: the UTF-8 helper bounds only the retained prefix, not its output

`packages/validation/src/supervisor/runtime/shared/supervisorEvidence.ts:120-136` now truncates the source text on code-point boundaries using UTF-8 bytes, but it fills the complete limit before appending the newline and truncation marker. A nominal 4,000-byte call therefore produced 4,020 output bytes. The regression at `packages/validation/test/supervisor/stimulus/coverage/argsPathsArtifacts.ts:76-84` checks only the prefix while its title claims the evidence excerpt is bounded.

Either reserve marker bytes so the complete returned string fits the limit, or rename and document the parameter as a retained-source-byte limit and do not use the result as a total persisted-byte budget.
