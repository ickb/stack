## High Findings

### 1. Confirmation depth can succeed for an orphaned transaction

`packages/sdk/src/send/wait_transaction.ts:60-70` caches the first committed response, then `:150-166` checks only tip height against that cached block number. After a reorg removes or rejects the transaction, a replacement chain reaching the required height returns the stale response as confirmed. Refresh transaction status/inclusion on every confirmation poll, reset on missing or pending, fail on rejection, and test committed-to-missing/rejected/re-included transitions.

### 2. Public DAO builders can exceed the immutable 64-output limit

`packages/dao/src/dao.ts:114-138`, `:148-201`, and `:211-270` return DAO transactions without invoking `assertDaoOutputLimit` at `packages/dao/src/dao_output_limit.ts:16`; `packages/core/src/logic.ts:132-147` can append another DAO output through the unchecked path. Focused construction produced 65-output DAO transactions. Enforce the deployed Nervos DAO limit on each public builder's result, including pre-existing outputs.

### 3. Timed-out detached commands can leave descendants running

`packages/node-utils/src/process.ts:320-329` schedules process-group TERM/KILL, but leader close clears the escalation timer at `:283-285` and `:390-396`. If the leader exits on TERM while a descendant ignores it, validation reports timeout completion while the descendant continues. Preserve group escalation through the grace period and test a real leader-exits/descendant-survives process tree.

### 4. Production updates are neither rollback-safe nor readiness-checked

`scripts/ickb-bot-systemd-update.sh:298-303` stops the only service before mutating the checkout and dependencies in place. A pull/install/check failure leaves it stopped, concurrent updaters are not serialized, and `Type=simple` start/status can succeed before bot preflight finishes. Prepare an immutable sibling release under a lock, switch atomically, wait for bounded application readiness, and roll back on failure.

### 5. Pending transaction ownership is lost across document reloads

`apps/interface/src/query/pendingTransactionQuery.ts:35-55` stores ownership only in one in-memory `QueryClient`, and `:83-88` records the hash only after the signer promise resolves. Reload/crash after broadcast acceptance forgets the financial intent and permits another submission. Persist a versioned chain/account/hash record at the broadcast boundary, validate/hydrate it on startup, and test a new `QueryClient` plus a crash before the send promise resolves.

## Medium Findings

### 6. Public chain scans have no aggregate work bound

`packages/utils/src/utils.ts:25-39` materializes every yielded cell; DAO, Core, Order, and SDK callers then filter, convert, or resolve the complete arrays. `pageSize` is explicitly only an RPC page size. Large public pools can cause unbounded RPC work, heap use, stale projections, and sequential origin lookups independently of matching budgets. Add explicit aggregate cell/group/lookup limits and surface truncation or resumable cursors rather than silently presenting partial state as complete.

### 7. Wait parameter domains can disable or collapse deadlines

`packages/sdk/src/send/wait_transaction.ts:49-55` accepts `NaN` and timer-overflow durations; `:302-304` passes the remaining duration directly to `setTimeout`. `NaN` disables checks/timers, while a 3,000,000,000 ms probe fired in about 1 ms. Validate timeout, interval, and confirmation domains and re-arm supported long waits in bounded timer chunks.

### 8. Match accounting is independent from assembled outputs

`packages/order/src/matching/match_types.ts:10-27` exposes caller-supplied deltas beside partial outputs, while `packages/order/src/io/order_transaction.ts:51-88` assembles only the partials. Bot planning consumes the independent deltas at `packages/bot/src/runtime/transaction.ts:147-153`. Derive effects once from validated inputs/replacement outputs at assembly, then return them or reject inconsistency.

### 9. Unattended interface confirmation still has no aggregate deadline

`apps/interface/src/action/actionTransaction.ts:179-192` composes fresh 60-second windows in `for (;;)`. Manual cancellation works, but a pending/dropped/unreachable transaction polls forever and never exposes automatic hash-preserving retry. Apply one aggregate attempt deadline and prove expiry retains the hash without rebroadcast.

### 10. The production lazy-load retry repeats the same rejected import

`apps/interface/src/app/lazyInterface.ts:5` always imports one module URL; `apps/interface/src/app/loadInterface.tsx:11-14` only wraps that loader in a new `React.lazy`. Browser-cached chunk/evaluation rejection therefore survives `Try again`; the test substitutes a loader that changes outcome. Reload the document or use a genuinely distinct module URL and test the production recovery path.

### 11. Checked integer codecs accept unsafe JavaScript numbers

`packages/utils/src/codec.ts:46-67` delegates to `ccc.numFrom` without rejecting unsafe numeric inputs. `9007199254740993` is rounded before the checked Uint64/Uint128 codecs serialize it. Reject non-safe `number` values and require bigint or decimal strings beyond the safe range.

### 12. Forced credential rotation replaces the known-good file before validation

`scripts/ickb-bot-systemd-credential.sh:147-149` installs the encrypted temporary file over the live credential before decrypting and validating the destination. Interruption or final validation failure destroys the previous valid credential. Validate the temporary ciphertext first, set final mode, atomically rename, and sync the containing directory.

### 13. Active production logs and launch history are unbounded

`scripts/bot/launcher/runtime/execute.ts:36-45` writes fixed sinks for the process lifetime, while quota enforcement runs only before launch at `scripts/bot/launcher/storage/prepare.ts:41-48` and excludes the active slot at `storage/retention.ts:16-25`. `launches.ndjson` is append-only and read wholly at `logs.ts:95-102`. Rotate active output by bytes and bound/compact launch history.

### 14. Storage-disabled browsers can fail before fallback handling

`apps/interface/src/app/Interface.tsx:17`, `wallet/WalletGate.tsx:32`, and `wallet/interfaceLanding.tsx:54-58` evaluate `globalThis.localStorage` before entering helper `try` blocks. A throwing storage getter prevents the interface from rendering. Acquire storage inside guarded helpers and test a throwing global getter.

### 15. Config validation accepts RPC URL userinfo unsupported by Fetch

`packages/node-utils/src/runtime_config.ts:252-276` accepts HTTP(S) URLs with username/password, then `packages/node-utils/src/chain.ts:109-117` passes them to CCC Fetch transport. Node Fetch rejects credential-bearing request URLs before sending. Reject URL userinfo centrally or support an explicit authorization-header transport.

### 16. DAO-boundary fee completion ignores valid signer-owned plain outputs

`packages/sdk/src/client/sdk_base.ts:155-177` chooses only receipt, order-master, and owner-marker fee-change outputs. At 64 outputs, an otherwise valid signer-owned plain output is ignored and completion rejects rather than avoiding output 65. Retain protocol-output priority, then use a signer-owned plain output as the fallback target.

## Low Finding

### 17. Empty-pool matching masks malformed configuration

`packages/order/src/matching/order_matching.ts:24-35` returns `complete` for an empty pool before exchange-rate and allowance-step validation in `order_match_context.ts:62-145`. Validate the entire request before the empty-pool fast path so configuration does not begin failing only when the first order appears.
