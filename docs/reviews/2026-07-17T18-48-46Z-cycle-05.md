## Findings

### Medium: confirmation has no automatic overall deadline

`apps/interface/src/action/actionTransaction.ts:178` repeats every 60-second timeout indefinitely. The mounted UI now exposes a working `stop waiting` command, but an unattended pending, dropped, or unreachable transaction never transitions automatically to the retry-confirmation state.

Apply an overall confirmation-attempt deadline that preserves the pending hash and enables retry without rebroadcast. This is an aggregate lifecycle contract and requires a bounded-time behavior test; the literal-`Infinity` ESLint rule cannot prove it.

### Medium: same-account remount can miss a late broadcast hash

`apps/interface/src/action/Action.tsx:67` reads the pending hash only in a `useState` initializer. Wallet-config replacement remounts the action through the identity key at `apps/interface/src/view/WalletAppView.tsx:77`.

If remount completes before a detached signer call resolves, `apps/interface/src/action/actionTransaction.ts:124` later publishes the returned hash to React Query, but the new action is not subscribed to that update. It can remain eligible to broadcast another transaction for the same account. Existing tests prove late cache publication, not remount-before-publication behavior.

Make pending transaction state reactive for the exact chain/address identity, or otherwise transfer late ownership to the remounted action. Add a remount-before-late-hash test that proves a second broadcast is unavailable while the first hash remains unresolved.

### Medium: SDK abort and timeout do not preempt an in-flight request

`packages/sdk/src/send/wait_transaction.ts:52` checks the abort signal and absolute timeout only between awaited client calls. If `getTransaction`, raw JSON-RPC, or `getTipHeader` does not settle, neither abort nor timeout can complete the public operation until that request returns.

A focused client with unresolved `getTransaction` kept both an abort and a one-millisecond timeout pending beyond 20 milliseconds; each settled only after the request was released. The interface's outer abort race keeps its UI responsive, but direct SDK consumers still observe the broken cancellation/deadline contract.

Apply cancellation and the absolute deadline at each awaited client boundary. Add tests for abort and timeout while a client request is in flight. Static lint cannot prove promise settlement behavior.

### Low: lazy-load retry reuses a rejected module promise

`apps/interface/src/app/loadInterface.tsx:3` creates one module-level `React.lazy` instance, which caches a rejected loader promise. `apps/interface/src/app/ErrorBoundary.tsx:33` clears only boundary state, then renders the same lazy instance and receives the cached rejection again.

A transient chunk-load failure therefore requires a page reload despite the visible `Try again` command. Recreate the lazy loader on retry or reload the document, and add a reject-then-resolve module-loading test.

### Medium: broad Knip entries hid unused script exports

The cycle-start `knip.jsonc` treated every `scripts/**/*.ts` file as an entrypoint. Knip excludes entrypoint exports by default, so a green standard run omitted unused private script surface.

A focused entry-export run found 44 unused values and 33 unused types across 17 script files. This cycle replaced the broad entry glob with ten actual CLI roots plus `scripts/test/**/*.ts`, which the Node test runner executes directly, and enabled root-scoped entry-export analysis. Knip now reports all 77 findings while preserving zero unused-file, dependency, unlisted, unresolved, binary, catalog, and duplicate diagnostics.

Review those exports and remove or internalize unneeded surface. Some may be intentional test seams, but they currently have no importers. Knip is the correct owner; no custom rule was added.
