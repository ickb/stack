## Current Findings

### High: ambiguous pre-admission broadcast failures can lock every product on a nonexistent transaction

`signAndSendTransaction` records the signed local hash before RPC and wraps every transport failure with that hash at `packages/sdk/src/send/sign_and_send_transaction.ts:27-54`. This preserves identity when a node may have accepted the transaction, but the same path is used when a failure occurs before any admission. The interface durably stores the hash before RPC and then retains the frozen conversion for confirmation at `apps/interface/src/query/pendingTransactionQuery.ts:144-160` and `apps/interface/src/action/actionTransaction.ts:95-120`. The bot classifies every broadcast error without a conflicting node hash as ambiguous and enters repeated confirmation windows at `packages/bot/src/bot/loop.ts:243-267,285-351`. Validation likewise waits on the recorded hash.

The current `ICKB-022` audit reproduction confirms record-before-RPC, wrapping of any send failure, and the unbounded bot confirmation path. Existing interface and bot tests intentionally preserve the hash after a forced pre-admission failure. If no node has the transaction, these flows cannot make progress and cannot safely rebuild.

Retain the signed transaction bytes with the submission owner. Reconcile status for a bounded interval, then rebroadcast the exact same bytes/hash when admission remains unknown; never rebuild or discard identity until the original transaction is terminally reconciled.

### High: forwarded shutdown can orphan detached process-group descendants

`withProcessSignalForwarding` signals children currently present in `activeChildren` and arms escalation at `packages/node-utils/src/process.ts:162-184`, but clears the escalation timer as soon as `run` returns at `packages/node-utils/src/process.ts:188-203`. A detached leader's close removes it from `activeChildren` at `packages/node-utils/src/process.ts:277-310`, even when group descendants survive. The timeout path separately tracks the process group until it disappears at `packages/node-utils/src/process.ts:322-375`; forwarded-signal cleanup does not.

The current `ICKB-023` probe confirmed group forwarding and escalation but showed `forward-tracks-group=false` while timeout cleanup tracks it. Detached validation and supervisor commands can therefore leave SIGTERM-ignoring descendants alive after their leader exits.

Reuse the timeout path's process-group cleanup owner for forwarded signals and await group disappearance independently of leader lifetime. Add a descendant regression for forwarded SIGTERM, not only timeout cleanup.

### High: bounded withdrawal search silently misses a better exact later subset

The optimal subset search considers only the first 30 deposits at `packages/sdk/src/withdrawal/withdrawal_best_fit.ts:11,53-67,124-152`; all-candidate fallback is greedy first-fit. The current `ICKB-025` reproduction supplied 30 early 110,000-unit deposits followed by 80,000, 60,000, and 40,000. The selector chose 80,000 even though the later 60,000 + 40,000 exactly fills 100,000. Conversion planning can then create an avoidable remainder order despite the whitepaper requirement to maximize directly withdrawn iCKB.

Either prove the optimum over all eligible deposits with a bounded algorithm or return explicit incompleteness so planning cannot present a heuristic result as maximal. Raising the prefix size only changes which valid combinations are missed.

### High: aggregate financial-state pagination remains intentionally unbounded

`collectPagedScan` rejects missing and repeated cursors but explicitly permits unlimited advancing pages at `packages/utils/src/utils.ts:60-101`. All cell collectors and SDK financial-state paths still materialize the complete result. The audit dependency gate reproduced `ICKB-001` through a bounded verifier timeout.

Add one aggregate page/item budget and typed exhaustion error at the collector owner, define its scope across cached and multi-lock scans, and reject complete state construction on exhaustion. Caller-local caps or partial state would duplicate policy and corrupt financial conclusions.

### High: failed migration restoration can report success while the legacy bot is offline

The interval migration rewrite now accepts the default shipped legacy unit, builds the candidate from the invoking clean checkout, restores through one path, and avoids switching after a failed candidate stop. However, `restore_legacy_migration` restores files and runs `systemctl start` at `scripts/ickb-bot-systemd-install.sh:356-385` without proving the service stays active or becomes ready, then deletes the candidate root and unit backup. A failure-injected start returned success while a later activity check failed; restoration still returned status 0.

Restoration also leaves `log/bot` service-owned mode `0700` after the successful migration path changed it from the shipped root-owned `0755`, and its failed-stop message can claim no layout moved after cutover already selected the candidate. Save and restore legacy metadata, require bounded post-start health/readiness evidence, and preserve recovery artifacts until that proof succeeds.

### Medium: public RPC identity exposes credential-bearing pathnames

`publicRpcEndpointIdentity` removes userinfo and query parameters but returns `pathname` at `packages/node-utils/src/chain.ts:10-40`. That value enters bot preflight events and CLI output. The current `ICKB-018` reproduction retained `/v2/path-api-key`, while Stack policy treats credentialed RPC URLs as secret.

Publish only origin fields by default. A pathname should appear only through an explicitly configured, confirmed-public label; do not infer that URL path segments are non-secret.

### Medium: rejection recovery clears unrelated pending cache marks

Terminal rejection calls the global CCC `client.cache.clear()` at `packages/sdk/src/send/wait_transaction.ts:159-175,255-267`. The current `ICKB-020` reproduction showed an unrelated accepted transaction lose its transaction, input-unusable, and output-known marks. Existing tests assert the clear and rebuild-ready flag but do not preserve a concurrent survivor.

Do not declare rebuild readiness until the rejected transaction is rolled back transaction-scopingly or every unresolved survivor has been replayed in dependency order.

### Medium: readiness still trusts candidate-owned network constants

`scripts/ickb-bot-systemd-update.sh:405-415` now requires internally consistent expected and observed identity values, fixing cycle 18's contradictory-event case. It does not compare those values with a canonical identity independent of the candidate. A self-consistent mainnet genesis/prefix labeled as testnet still passed.

Take canonical identity from the current trusted release or one shared stable validator and test network swaps in both directions. Candidate assertions cannot independently authorize the candidate.

### Medium: shipped custom-log legacy deployments cannot migrate

The committed legacy installer supported `ICKB_BOT_LOG_ROOT`, but current compatibility accepts only the default command and `${deploy_dir}/log` at `scripts/ickb-bot-systemd-install.sh:293-341`. The exact default shipped unit now passes; an exact shipped custom-log unit fails closed before cutover. `apps/bot/README.md:171-178` describes migration from the shipped legacy unit without documenting that exclusion.

Either support and test the shipped custom-log shape, including safe ownership and containment, or state the compatibility boundary and required manual migration procedure explicitly.

### Medium: count-only retention leaves active logs and launch history byte-unbounded

The interval deleted the unsound active-quota and retention machinery. Current launcher storage uses 16 fixed run slots, truncating event/stderr files and resetting artifacts only when a slot is reused at `scripts/bot/launcher/logs.ts:23-37,86-111`; `launches.ndjson` remains append-only. `apps/bot/README.md:146,272-274` now accurately states the count-only contract and requires disk monitoring.

This is simpler and no longer falsely claims a byte quota, but one long run and launch history can still exhaust disk. Keep this as an explicit operational residual unless one serialized evidence owner can bound logs, artifacts, temporary bytes, and terminal records without fragmenting consumer evidence.

### Low: sampler binary search assumes timestamp monotonicity that consensus does not require

The sampler promises the first block whose timestamp meets the target but binary-searches header timestamps by height at `apps/sampler/src/index.ts:121-145`. CKB permits adjacent timestamp decreases. The `ICKB-019` counterexample selected block 3 although block 1 was the earliest match.

Implement a search whose result is valid without monotonic timestamps, or document and name the result as an approximate height estimate rather than an earliest block.
