## Findings

### High: candidate budget does not charge impossible Cartesian pairs

`packages/order/src/matching/order_match_search.ts:112` iterates every pair of directional frontier states. Impossible pairs are rejected at line 134 without claiming work. The upper-bound calculation at line 317 excludes pairs whose combined partial count exceeds `maxPartials`, so it can certify the search as within budget even though runtime still scans those pairs.

A valid dual-direction singleton with 10,000 atomic choices per direction, `maxPartials: 1`, and the default 100,000 budget completed with reported work `60,001` while actually visiting about 100 million pairs. It took 16.5 seconds. Observed scaling was 0.2 seconds at 1,000 choices, 1.6 seconds at 3,000, and 6.0 seconds at 6,000.

Impact: an apparently budget-compliant synchronous match can still stall bot and consumer processes. Charge pair visits before filtering, or organize traversal so impossible partial-count and duplicate-order regions are never crossed. This is a runtime complexity invariant; a regression test must compare reported work with actual pair visits.

### High: incomplete-empty matching suppresses maintenance and reports healthy inactivity

`packages/bot/src/runtime/transaction.ts:45` returns immediately when a bounded search is incomplete and has no best-so-far partial. It therefore bypasses collection and `planRebalance` at line 148. `packages/validation/src/supervisor/classification/supervisorBotClassificationB.ts:255` classifies the resulting `match_search_incomplete` skip as nonterminal `bot_no_action_skip`.

A default-budget reproduction with eight valid, unprofitable public order groups returned an incomplete empty match, skipped all actions, and was classified as healthy no-action. Running the same state with a complete empty match built a deposit rebalance. A second reproduction with two ordinary 100-CKB CKB-to-UDT orders and zero iCKB likewise suppressed a valid deposit, even though replenishing iCKB was the independent action needed before those orders could become matchable.

Route incomplete-empty search through ordinary collection/rebalance planning with zero useful-match floors while preserving the incomplete-search evidence. If no independent action remains, classify the explicit incomplete result as inspection-worthy rather than normal no-action coverage. This cross-package semantic contract requires producer-to-supervisor tests, not lint.

### Medium: finite polling windows compose into an infinite, unabortable operation

`apps/interface/src/action/actionTransaction.ts:92` wraps 60-second `waitTransaction` calls in `for (;;)`, swallowing every timeout. A permanently pending, dropped, or unreachable transaction never reaches the new retry-confirmation state; the action remains disabled.

The transaction hash is component-local state at `apps/interface/src/action/Action.tsx:58`, while the wallet selector remains active. Switching wallet or network unmounts the action, loses the recoverable hash, and leaves the prior polling loop running without cancellation.

Bound the complete confirmation attempt, surface timeout as the existing unresolved/hash-preserving state, retain that outcome across wallet-view replacement, and abort polling on unmount. The literal-`Infinity` lint rule cannot prove semantic boundedness; lifecycle deadline, unmount, and signer-replacement tests must own it.

### Medium: amount validation error is truncated and not related to its input

`apps/interface/src/view/Form.tsx:64` sets `aria-invalid`, but the validation reason at line 81 has no ID and no `aria-describedby` or `aria-errormessage` relationship. Its classes force `whitespace-nowrap`, `overflow-hidden`, and ellipsis.

On narrow or touch viewports, the full reason is not visible, and the `title` fallback is not reliably available. Assistive technology learns that the field is invalid but not why. Associate a wrapping error element with the input, announce changes appropriately, and add an accessibility relation assertion plus a narrow-viewport overflow test.

### Medium: incomplete-search `requiredWork` is a moving sentinel, not a requirement

`packages/order/src/matching/order_match_search.ts:301` caps upper-bound calculations at `candidateBudget + 1`, then publishes that capped value as `truncation.requiredWork`.

The same 100-iCKB case reports `requiredWork` 100,001 for budget 100,000, 100,002 for budget 100,001, and 1,000,001 for budget 1,000,000. This is only a lower-bound sentinel and cannot guide configuration or incident response.

Calculate the real bound or name the field `requiredWorkAtLeast` and document its saturation. This requires contract tests across several budgets; a naming lint would not prove the value semantics.

### Medium: API rewrite leaves mandatory documentation, dead-export, and coverage gates red

Existing lint correctly reports the migration debt:

- `lint:structure` reports 61 undocumented public methods across Core entities, Order entities, and flattened `IckbSdk` methods.
- Knip reports 35 unused exports in validation supervisor internals.
- Coverage runs all 1,277 Vitest tests, then fails at 99.93% statements, 99.72% branches, 99.93% functions, and 99.95% lines. Current gaps are predominantly interface action, retry, quote, form-state, wallet-app, and pending-view paths, plus a small match-search path.

These checks already own their respective contracts. Add contract-bearing TSDoc, remove or internalize dead exports, and add behavior tests for the missing branches rather than weakening thresholds.
