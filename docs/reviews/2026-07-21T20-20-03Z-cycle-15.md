## Current Finding

### Low: a reversed wall clock can forge a stop without terminal artifacts

`packages/validation/src/supervisor/preflight/supervisorPreflightStep.ts:41-47` first calls `commandTimeoutMs` to decide whether enough wall-clock budget remains. When it returns no timeout, the code invokes `stopForUnavailableWallClockBudget`, which recomputes the time through `wallClockBudgetStopDiagnostics` at `supervisorPreflightBudget.ts:29-48`. If the wall clock moves backwards enough between those adjacent reads, the first check says the command cannot start while the second says the stop condition no longer exists. `stopForWallClockBudget` then returns `undefined`, and `?? STOP_EXIT_CODE` converts that absence into exit 2 without writing a summary or incident.

A deterministic dependency-injected counterexample used times `[200000, 0]`, deadline `1000000`, and a 900-second command timeout. It returned `{ stop: 2 }` with no artifacts or classifications. This contradicts the returned-stop contract documented in `supervisorPreflightRun.ts:20-21,63-67`, and operators are instructed to treat a missing summary as unexpected in `packages/validation/src/supervisor/README.md:87-93`. Production reachability requires a sufficiently large non-monotonic `Date.now` adjustment between adjacent reads, so severity remains Low.

Make timeout selection and stop finalization consume one time/budget decision. Never convert an absent stop decision into a controlled-stop exit code; either finalize a required stop or recompute a usable timeout and continue.
